# Tooling and architecture audit — 22 October 2026

The comparison below uses upstream GitHub repositories, release pages, and official documentation. Versions in requirements.txt describe the environment actually installed for this app. Release pages can lag package indexes; a newer tag alone is not a quality or accuracy benchmark.

| Purpose | Existing approach | Current upstream reviewed | Decision implemented |
|---|---|---|---|
| Interface | Default Streamlit widgets, old width APIs, disappearing results | [Streamlit releases](https://github.com/streamlit/streamlit/releases), October 2026 release series | Keep installed 1.66.1; replace the UI with a responsive workspace, previews, diffs, batch review, source panels, and current width APIs. |
| Agent orchestration | Fixed retrieve/expand/generate sequence labeled agentic | [LangGraph 1.2.16](https://github.com/langchain-ai/langgraph/releases), [official RAG workflow](https://docs.langchain.com/oss/python/langgraph/agentic-rag) | Adopt LangGraph: plan a search, retrieve, grade evidence, retry once if weak, then answer or abstain. The answer streams after retrieval completes. |
| Retrieval | Dense vectors only | [BM25S](https://github.com/xhluca/bm25s) | Add BM25S 0.3.14 lexical retrieval and reciprocal rank fusion with semantic results. Search each requested document so one cannot crowd out the other. |
| Embeddings and reranking | Reload MiniLM in four components; repeated graph embedding | [Sentence Transformers 6.2.0](https://github.com/huggingface/sentence-transformers/releases) | Reuse one cached text model, reuse indexed embeddings for graph construction, and add a configurable local cross-encoder relevance check. Keep the small English MiniLM default for CPU latency. No claim it is the strongest multilingual model. |
| Vector database | Every session writes to the same Chroma collection | [Chroma releases](https://github.com/chroma-core/chroma/releases), stable 1.5.9; exclude development prereleases | Keep stable Chroma; give each comparison a UUID collection, preserve provenance, and delete its collection on reset/replacement. |
| Document parsing | PyMuPDF/pdfplumber/python-docx | [PyMuPDF releases](https://github.com/pymupdf/PyMuPDF/releases), [pdfplumber releases](https://github.com/jsvine/pdfplumber/releases), [Docling 2.141.0](https://github.com/docling-project/docling/releases) | Keep the installed native text/table parsers for the PDF/DOCX workflow. Validate uploads, preserve page references, and include table content in retrieval. Docling is an alternative for OCR, reading-order inference, and richer formats, not an installed backend here. |
| Image similarity | CLIP API mismatch hidden by zero vectors | [Transformers CLIP implementation](https://github.com/huggingface/transformers/tree/main/src/transformers/models/clip) | Keep CLIP for semantic image matching, share its model, support the current projected-feature output, and surface inference failures. It does not detect every pixel or chart-value change. |
| Graph retrieval | Unbounded section cliques and regex terms called a knowledge graph | [Microsoft GraphRAG](https://github.com/microsoft/graphrag), [LightRAG](https://github.com/HKUDS/LightRAG), [LlamaIndex](https://github.com/run-llama/llama_index/releases) | Keep a bounded document relationship graph: adjacent passages, top semantic neighbors, and shared named terms. This is not entity/relation extraction, community summarization, or a claim to implement Microsoft GraphRAG. Those systems remain alternatives for larger collections. |
| Chat provider | Old unavailable model; unbounded context history | [Groq Python SDK](https://github.com/groq/groq-python/releases) and account model availability checked through the API | Keep Groq 1.7.0 and configurable GROQ_MODEL. Bound history and context, include stable source IDs, treat documents as untrusted evidence, and commit history only after a completed response. |
| Similarity | Directional best matches; absent tables inflate the total | Local scorer review and regression tests | Use both matching directions, clamp cosine roundoff, exclude jointly absent modalities, penalize content found only on one side, and expose effective weights. Scores are not calibrated probabilities. |
| Reproducibility | Unbounded minimum versions; two inconsistent requirements files | Installed environment and pip dependency validation | Pin direct dependencies, keep one requirements list, add a lock snapshot and a development browser-test dependency list. |

## Design choices and limits

Framework changes are based on fit for this local application, not repository stars. LangGraph supplies conditional execution; it does not improve retrieval automatically. Lexical fusion and reranking need evaluation on a representative document collection before accuracy claims. Reranker values are ranking signals, not probabilities: Groq separately checks the selected evidence for relevance, with a local relevance fallback if that check is unavailable. Planning, evidence grading, and answering can each make a provider request; weak evidence adds at most one broader retrieval attempt.

The app supports text-bearing PDFs and DOCX. Scanned PDFs need an OCR text layer; unsupported scans produce an actionable error. Word physical pagination is not inferred. Text diffs show extracted text and are capped at 5,000 lines per viewer. Layout analysis is heuristic. Batch review is limited to 10 candidates. The local in-memory index is rebuilt after a server restart. Extracted source evidence is sent to Groq for chat; local comparisons do not require a cloud key.

PyMuPDF licensing must be evaluated for the intended redistribution/deployment. This work verifies local Windows behavior; it is not a Linux deployment certification or a comprehensive security review.
